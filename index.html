U1

Low-latency Ethernet market-data decoder

SystemVerilog on a Xilinx Zynq-7020, July 2026 to now

In shortCustom digital hardware on an FPGA (a reprogrammable chip) that reads stock-exchange messages straight off an Ethernet cable and decodes each one in about 73 nanoseconds in simulation.

A Nasdaq TotalView-ITCH 5.0 parser that takes raw Ethernet off the wire and hands out decoded order-book messages, entirely in FPGA fabric.

  • I wrote the Ethernet MAC, IPv4/UDP and MoldUDP64 parsers to work cut-through: fields are decoded while the frame is still arriving, and a bad checksum at the end rolls the work back.
  • I designed a Gray-coded async FIFO to carry data from the 125 MHz PHY clock to the 200 MHz core clock, and sized it from the clock ratio and frame length.
  • I built a 10-test cocotb regression that compares the RTL against a Python golden model, with fault injection: 7,430 records, zero mismatches.
  • I scripted the Vivado build in Tcl, captured RGMII with IDELAYE2/IDDR and BUFIO/BUFR clocking, and closed timing at 200 MHz (WNS +0.185 ns).

RV32IM five-stage pipelined RISC-V core

SystemVerilog on a Xilinx Zynq-7020, March to July 2026

In shortA processor I designed from scratch: it runs standard RISC-V programs, passes all 48 official tests, and matched a reference simulator over 12.5 million instructions.

An in-order CPU that runs real RISC-V programs on the FPGA, with the Zynq's ARM core loading programs and acting as the console.

  • I designed the five-stage pipeline with full operand forwarding, a load-use interlock and precise exceptions (Zicsr).
  • I built the multiplier on DSP48 slices, pipelined so it doesn't limit the clock.
  • I set up the verification: the official riscv-tests and RISCOF suites, plus an instruction-by-instruction lockstep check against the Spike reference simulator.
  • I benchmarked it with CoreMark in simulation, with a CPI breakdown from hardware performance counters.

U3

NanoGuard: FPGA pre-trade risk checks you can change in minutes

Rutgers TechStart 2026, finalist (top 5 of the competition), team of six

In shortA startup prototype, and top-5 finalist at Rutgers TechStart 2026, that lets compliance staff change hardware trading-risk checks in plain English instead of waiting weeks for engineers.

Brokers with direct market access must check every order before it reaches the exchange (SEC Rule 15c3-5). FPGA checks are fast, but changing a rule takes weeks of engineering. NanoGuard was my idea for closing that gap, and I built the working prototype we demoed live to the judges.

  • I wrote the Verilog risk-check module: restricted list, max order size, price collar and capital limit, in a 2-stage pipeline with configurable registers.
  • I built the Python pipeline: the LLM rule builder with a constrained tool schema, a validator against the template catalog, a compiler to register values, and the approval step.
  • I verified the RTL against a Python reference model on 100,000 random orders, with zero mismatches, and built the Streamlit demo we ran on stage.
  1. AI proposesA compliance officer types a rule in plain English. An LLM maps it to a pre-verified hardware template.
  2. Tests verifyThe rule is compiled to register values and checked in simulation with Icarus Verilog.
  3. A human approvesNothing reaches the hardware without sign-off. Out-of-scope requests become engineering tickets.
  4. Hardware enforcesThe FPGA checks every order in about 2 clock cycles. The AI is never in the trading path.

AeroBin: a clip-on fill-level sensor for any waste container

Custom ESP32-C3 board in KiCad, Verizon Smart Campus Competition 2026–27

In shortA circuit board I designed for a clip-on sensor that reports how full a waste container is, for the Verizon Smart Campus Competition.

AeroBin clips onto a bin that's already in place and reports how full it is, so pickups happen when a container needs one instead of on a fixed schedule. It won first place in last year's Verizon Smart Campus Competition, which took the team to Verizon headquarters. This year we're building it to track any waste container and to earn real revenue for Verizon. We're developing it with Verizon's engineering mentors, and Qualcomm has offered its technology to help.

  • I defined the hardware architecture and chose the sensor, power path and microcontroller.
  • I designed the V1 board in KiCad: a 45 × 32 mm two-layer PCB around an ESP32-C3-MINI-1 module, with a VL53L1CX time-of-flight sensor on I²C that measures the distance down to the waste.
  • I built the power path: USB-C input with USBLC6 ESD protection, an MCP73831 Li-Po charger, a JST-PH battery connector, an RT9080 3.3 V regulator, and a divider so the firmware can read the battery voltage.
  • I designed it for bring-up: seven labeled test points (3V3, VBAT, GND, UART TX/RX, I²C SCL/SDA), BOOT and EN buttons, a status LED, and native USB for flashing.
  • I'm designing the 3D-printed enclosure the board mounts in.

V1 connects over Wi-Fi so we can demo a working unit now; the product is planned to run on Verizon LTE-M.

Crusoe builds and runs AI data centers. I worked across the reliability, controls and commissioning teams. Most of my summer went to one problem: the same piece of equipment had a different name in the maintenance system, in SCADA and in the cloud dashboards, so nothing could be matched automatically.

  • I proposed a five-level naming standard for modular sites, adapted from a seven-level standard written for large buildings, and measured row by row how far the live SCADA tags sat from it.
